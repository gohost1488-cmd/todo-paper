# Отчёт аудита безопасности (devsec)

Независимый проход по коду: `index.html`, `assets/app.js`, `assets/styles.css`,
`.github/workflows/pages.yml`, `SECURITY.md`. Дата: 06.11.2026.

## Вердикт

Одна находка низкой серьёзности. Остальные проверенные риски по исходному коду не подтверждены:
пути для XSS через пользовательский текст нет, HTML из данных не собирается,
prototype pollution через JSON из `localStorage` не проходит, внешней передачи данных нет,
объём загружаемых задач ограничен (500 записей, 200 символов).

## Находки

| Severity | Место | Проблема | Что делать |
|---|---|---|---|
| low | `index.html:6–7`, `SECURITY.md` | CSP задана через `<meta>` и не ограничивает встраивание страницы во фрейм: сайт можно встроить на чужую страницу (clickjacking) | Задать `Content-Security-Policy: frame-ancestors 'none'` (и `X-Frame-Options: DENY`) HTTP-заголовком на хостинге. GitHub Pages свои заголовки не отдаёт, поэтому здесь это недоступно и зафиксировано в ограничениях |

## Что проверялось и не подтвердилось

- **XSS через текст задачи** — вставка идёт только через `textContent`;
- **XSS через правку** — `contenteditable="plaintext-only"`, результат снова через `textContent`;
- **Prototype pollution** — поля из `localStorage` проверяются по типам, лишние ключи не копируются;
- **Подмена разметки** — CSP `script-src 'self'`, `object-src 'none'`, `base-uri 'none'`;
- **Утечка данных** — `connect-src 'none'`, внешних запросов нет;
- **DoS через объём** — жёсткие лимиты на число задач и длину текста;
- **Секреты** — в репозитории отсутствуют, деплой использует `GITHUB_TOKEN` внутри workflow.

## Как закрыть единственную находку

Вариант 1: перенести сайт за Cloudflare (или любой прокси с заголовками) и добавить
`frame-ancestors 'none'` + `X-Frame-Options: DENY`.
Вариант 2: оставить как есть — риск низкий (нет аутентификации, нет чужих данных,
максимум последствий — пользователь нажмёт «удалить» у себя же).
