# Безопасность

Проект — статическая страница без сервера. Секретов, ключей и внешних адресов в нём нет
по построению: отдавать нечего, кроме HTML, CSS и JS.

## Что защищено и как

| Риск | Что сделано | Как проверить |
|---|---|---|
| XSS через текст задачи | текст вставляется только через `textContent`; `innerHTML` для данных пользователя не используется нигде | `grep -n innerHTML assets/app.js` → пусто; тест «HTML из ввода не исполняется» |
| Внедрение через редактирование | `contenteditable="plaintext-only"`, результат проходит через `textContent` | тест правки, ручная проверка |
| Подмена разметки/инъекция скрипта извне | CSP: `default-src 'self'; script-src 'self'; style-src 'self'; connect-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'` | `curl -sI` страницы, консоль браузера: нарушений нет |
| Внешние соединения и утечка данных | нет сторонних скриптов, шрифтов, аналитики; `connect-src 'none'` | тест «нет внешних сетевых запросов» |
| Переполнение хранилища | лимит 500 задач, 200 символов, перехват `QuotaExceededError` | ручная проверка, код `save()` |
| Битые данные в `localStorage` | `JSON.parse` в `try/catch`, поля проверяются по типам и обрезаются | подмена значения в DevTools → страница не падает |

## Секреты

- в репозитории нет `.env`, ключей и токенов; `.gitignore` исключает `node_modules`, `.env*`, `*.log`;
- публикация на GitHub Pages идёт через `.github/workflows/pages.yml` с `GITHUB_TOKEN`,
  который GitHub выдаёт workflow на время выполнения — в коде его нет;
- сторонние сервисы не используются, поэтому нечего и компрометировать.

Проверка перед публикацией:

```bash
grep -rInE "(api[_-]?key|secret|token|password|BEGIN [A-Z ]*PRIVATE KEY)" \
  --exclude-dir=node_modules --exclude-dir=.git . || echo "секретов не найдено"
```

## Данные пользователя

Задачи лежат только в `localStorage` браузера пользователя и никуда не отправляются.
Очистка данных сайта в браузере удаляет их полностью.

## Известные ограничения

- CSP задан через `<meta>`: директива `frame-ancestors` в таком виде игнорируется
  (её можно задать только HTTP-заголовком). Если понадобится защита от встраивания
  в iframe, нужен сервер/CDN с заголовками.
- GitHub Pages не позволяет задавать произвольные заголовки ответа, поэтому HSTS и
  `frame-ancestors` здесь недоступны; HTTPS при этом включён по умолчанию.
